# WVP-GB28181 摄像头点播收流失败修复说明

## 问题根源

### 1. **致命问题：网络驱动模式错误** ❌
- **原配置**：`networks.media-net.driver: host`
- **问题**：Docker for Windows 不支持 host 网络模式！
- **后果**：
  - 所有容器的端口映射被忽略
  - 容器间通信失败
  - 摄像头无法访问正确的 RTP 端口
  - 流媒体服务无法正常工作

### 2. **端口配置重复** ❌
- 原配置中 `30000-30500:30000-30500/udp` 重复出现
- Docker Compose 不允许端口定义重复

### 3. **IP 地址配置错误** ❌
- ZLMediaKit 的 config.ini 中 `listen_ip=::` 和 `ip=47.93.211.98` 配置不当
- 应该监听 `0.0.0.0`，让容器内部可访问

### 4. **端口冲突** ⚠️
- WebHttp=8080 与 ZLMediaKit 的 HTTP 端口冲突
- 需要将 nginx 端口改为 8088

## 已修复内容

### 1. docker-compose.yml 修复

```yaml
# ✅ 网络模式改为 bridge（默认）
networks:
  media-net:
    driver: bridge  # 从 host 改为 bridge

# ✅ polaris-media 端口配置优化
polaris-media:
  ports:
    - "6080:6080/tcp"                         # HTTP 播流（必须暴露）
    - "${MediaRtmp:-10001}:${MediaRtmp:-10001}/tcp"    # RTMP
    - "${MediaRtmp:-10001}:${MediaRtmp:-10001}/udp"
    - "${MediaRtsp:-10002}:${MediaRtsp:-10002}/tcp"    # RTSP
    - "${MediaRtsp:-10002}:${MediaRtsp:-10002}/udp"
    - "${MediaRtp:-10003}:${MediaRtp:-10003}/tcp"      # RTP
    - "${MediaRtp:-10003}:${MediaRtp:-10003}/udp"
    - "30000-30500:30000-30500/udp"           # RTP 动态端口范围（仅一次）
```

**关键修复点**：
- ✅ 移除重复的端口映射
- ✅ 移除了 8160、8080、8081 端口（避免冲突）
- ✅ 6080 端口必须暴露，用于 HTTP 流播放
- ✅ 使用环境变量默认值，避免变量未定义问题

### 2. .env 文件修复

```bash
# ✅ 修正端口定义
MediaRtmp=10001
MediaRtsp=10002
MediaRtp=10003         # 从 "30000-30500" 改为单一端口

# ✅ 避免端口冲突
WebHttp=8088           # 从 8080 改为 8088（避免与 ZLM 冲突）
WebHttps=8089          # 从 8081 改为 8089
```

### 3. ZLMediaKit config.ini 修复

```ini
[general]
listen_ip=0.0.0.0      # ✅ 从 :: 改为 0.0.0.0，监听所有网卡
auto_detect_ip=1       # ✅ 从 0 改为 1，自动检测 IP

[http]
ip=0.0.0.0             # ✅ 从 47.93.211.98 改为 0.0.0.0，容器内部监听所有接口
```

**关键说明**：
- 容器内部监听 `0.0.0.0`，确保可从其他容器和主机访问
- 公网 IP（47.93.211.98）通过环境变量 Stream_IP 和 SDP_IP 传递给 WVP
- WVP 会在 SDP 协商和流地址返回时使用公网 IP

## 阿里云安全组配置

必须开放以下端口（TCP 和 UDP）：

| 端口范围 | 协议 | 用途 |
|---------|------|------|
| 8088 | TCP | Nginx Web 访问 |
| 18978 | TCP | WVP 管理后台 |
| 8160 | TCP/UDP | GB28181 SIP 信令 |
| 10001 | TCP/UDP | RTMP 收流 |
| 10002 | TCP/UDP | RTSP 收流 |
| 10003 | TCP/UDP | RTP 收流 |
| 6080 | TCP | ZLMediaKit HTTP 流播放 |
| 30000-30500 | UDP | RTP 动态端口范围（重要！） |

**阿里云安全组配置示例**：
```
入方向规则：
- 协议：TCP，端口：8088，源：0.0.0.0/0
- 协议：TCP，端口：18978，源：0.0.0.0/0
- 协议：TCP/UDP，端口：8160，源：0.0.0.0/0
- 协议：TCP/UDP，端口：10001-10003，源：0.0.0.0/0
- 协议：TCP，端口：6080，源：0.0.0.0/0
- 协议：UDP，端口：30000-30500，源：0.0.0.0/0（必须！）
```

## 常见问题排查

### 1. 点播后无法播放
**检查项**：
```bash
# 1. 查看 WVP 日志
docker-compose logs polaris-wvp | tail -100

# 2. 查看 ZLMediaKit 日志
docker-compose logs polaris-media | tail -100

# 3. 检查流是否生成
curl http://localhost:6080/index/api/getMediaList
```

**常见原因**：
- 阿里云安全组未开放 30000-30500 UDP 端口
- 摄像头无法连接到公网 IP 的 SIP 端口（8160）
- SDP 协商失败（检查 SDP_IP 配置）

### 2. 容器无法启动
```bash
# 查看详细错误
docker-compose logs [service-name]

# 检查配置文件语法
docker-compose config
```

### 3. 端口已被占用
```bash
# Windows 查看端口占用
netstat -ano | findstr "8088"
netstat -ano | findstr "10001"

# 结束占用进程
taskkill /PID [进程ID] /F
```

### 4. 摄像头注册失败
**检查**：
- 摄像头 SIP 服务器 IP 是否配置为公网 IP（47.93.211.98）
- 摄像头 SIP 服务器端口是否为 8160
- SIP 域和设备 ID 是否匹配
- 防火墙是否开放 8160 UDP 端口

## 配置说明

### Stream_IP vs SDP_IP
- **Stream_IP**：用于生成流播放地址，返回给前端播放器
- **SDP_IP**：用于 SIP SDP 协商，告诉摄像头往哪个 IP 推流
- **建议**：两者都配置为阿里云公网 IP（47.93.211.98）

### 容器间通信
- 使用 **bridge 网络模式**，容器间通过服务名通信
- 例如：WVP 访问 ZLMediaKit 使用 `http://polaris-media:6080`
- 外部访问使用公网 IP + 映射端口

### RTP 端口范围
- **单端口模式**：MediaRtp=10003
- **多端口模式**：30000-30500（用于并发多路流）
- 推荐使用多端口模式，兼容性更好

## 修复总结

| 问题 | 原因 | 修复方案 | 优先级 |
|------|------|---------|--------|
| 网络驱动错误 | host 模式不支持 Windows | 改为 bridge 模式 | 🔴 最高 |
| 端口重复 | 配置失误 | 移除重复端口 | 🔴 最高 |
| IP 配置错误 | 容器内监听公网 IP | 改为 0.0.0.0 | 🔴 最高 |
| 端口冲突 | nginx 与 ZLM 冲突 | nginx 改为 8088 | 🟡 中等 |

修复后，系统应该能够正常工作。如果仍有问题，请检查日志并按照上述排查步骤逐一验证。
